# Tasks: US-007

## Implementation Tasks
- [ ] T001 FR-US-007-001 (US-007-ac-1): For any authenticated administrator making an HTTP POST request to an endpoint under the /api/admin/* namespace without providing the required CSRF token via either the CSRF same-site cookie or the custom CSRF header, the system SHALL respond with HTTP status code 403 and a response body that conforms exactly to the agreed standard error schema: fields code, message, timestamp (in UTC), correlation_id, and path, and SHALL NOT include any sensitive data beyond those fields. (Trace: EP-001-R5, EP-001-R3).
- [ ] T002 FR-US-007-002 (US-007-ac-2): For any authenticated administrator making an HTTP POST request to an endpoint under the /api/admin/* namespace with a valid CSRF token present in a same-site cookie and a matching value in the custom CSRF header, the system SHALL NOT deny the request due to CSRF and SHALL allow the underlying admin operation to execute so that, if that operation completes successfully, the API response is an HTTP 2xx status code. (Trace: EP-001-R5). Note: The acceptance criterion does not specify the exact 2xx code or response body, only that the response is successful (2xx).
- [ ] T003 FR-US-007-003 (US-007-ac-3): For every admin POST request under /api/admin/* that is denied due to a CSRF failure (including missing or invalid CSRF cookie and/or header), when the 403 response is returned, the system SHALL emit a structured log entry that includes at least the correlation_id associated with the request and the request path, and SHALL explicitly exclude PII or other sensitive information from that log entry, in alignment with organizational logging standards. (Trace: EP-001-R6). Ambiguity: The specific log sink, log format, and full schema are not defined here and must be aligned with existing logging infrastructure.
- [ ] T004 FR-US-007-004 (US-007-ac-4): The CSRF validation behavior described in FR-US-007-001, FR-US-007-002, and FR-US-007-003 SHALL be applied uniformly to all HTTP POST endpoints under the /api/admin/* namespace, such that there are no admin POST endpoints in this namespace that bypass or implement a different CSRF enforcement mechanism, unless explicitly exempted by separate requirements. (Trace: EP-001-R5). Ambiguity: The exact list of endpoints under /api/admin/* is not defined in this story and must be confirmed elsewhere.

## Verification Tasks
- [ ] T005 Verify US-007-ac-1: Given an authenticated administrator, When making a POST to /api/admin/* without the CSRF header or cookie, Then the response is 403 with the standard error schema (code, message, timestamp in UTC, correlation_id, path) and no sensitive data (EP-001-R5, EP-001-R3).
- [ ] T006 Verify US-007-ac-2: Given an authenticated administrator, When making a POST to /api/admin/* with a valid CSRF token in a same-site cookie and matching custom header, Then the response is successful (2xx) (EP-001-R5).
- [ ] T007 Verify US-007-ac-3: Given any denied admin POST due to CSRF, When the response is returned, Then a structured log entry is recorded with the correlation_id and request path and without PII (EP-001-R6).
- [ ] T008 Verify US-007-ac-4: Given multiple POST endpoints under /api/admin/*, When requests are made, Then CSRF checks are applied uniformly across all of them (EP-001-R5).
- [ ] T009 Verify IMPACT: US-007-ac-1: Create automated tests (unit, integration, and/or API tests) that, for authenticated admin users, exercise POST requests under the admin namespace without CSRF header and/or cookie and assert 403 responses with the exact standard error schema fields (code, message, UTC timestamp, correlation_id, path) and verify absence of sensitive data.
- [ ] T010 Verify IMPACT: US-007-ac-2: Create automated tests that, for authenticated admin users, send POST requests under the admin namespace with a valid CSRF token in a same-site cookie plus matching custom header and assert successful 2xx responses, verifying that valid tokens do not cause erroneous denials or regressions.
- [ ] T011 Verify IMPACT: US-007-ac-3: Create tests that trigger CSRF-denied admin POSTs and verify that a structured log entry is emitted containing the correlation_id and request path and no PII or sensitive attributes, potentially via log-capture or mock logging sinks.
- [ ] T012 Verify IMPACT: US-007-ac-4: Create coverage across multiple distinct admin POST endpoints under the admin namespace to confirm that CSRF checks are enforced uniformly (both for valid and invalid/missing tokens), with no endpoint-specific bypasses or divergent behavior.
